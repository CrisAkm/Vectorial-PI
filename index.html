02 / 16 TEORÍA FUNDAMENTAL • PÁG. 80

Anatomía del Nodo Doblemente Ligado

Superando la limitación unidireccional de las listas simples mediante doble campo de liga.

Estructura Interna del Nodo 3 CAMPOS

1. Liga Izquierda (LI / Prev / Antecesor)

Apuntador que almacena la dirección de memoria del nodo anterior. Permite retroceder en la secuencia sin reiniciar la búsqueda desde la cabeza.

2. Sección Central (INFO / Dato / Carga Útil)

Espacio reservado para almacenar el valor o entidad (en los diagramas del libro denotado con la variable x, y o z).

3. Liga Derecha (LD / Next / Sucesor)

Apuntador que almacena la dirección de memoria del nodo siguiente, preservando el flujo hacia adelante.

¿Por qué adoptarlas? (Trade-off de Ingeniería)

Ventaja: Recorrido en ambas direcciones y borrado en tiempo $O(1)$ cuando se tiene la referencia del nodo.
Costo: Mayor consumo de memoria (dos punteros por nodo en lugar de uno).

Elementos Clave de la Figura III.18 ANÁLISIS TEXTUAL

Símbolo de "Tierra" o Masa Eléctrica

En las ciencias computacionales clásicas (representado con 3 líneas horizontales decrecientes), simboliza el valor NULL (nulo o vacío). Indica que el primer nodo no tiene antecesor y el último no tiene sucesor.

Puntero I (Inicio / Izquierda)

Apunta directamente al primer nodo de la lista. En pseudocódigo: p = I para iniciar recorridos de izquierda a derecha usando p = p->LD.

Puntero D (Derecho / Final)

Apunta directamente al último nodo de la lista. Permite comenzar recorridos en orden inverso de derecha a izquierda usando p = p->LI de forma inmediata.

Invariante de Consistencia

Para cualquier nodo intermedio $k$:
k == k->LD->LI == k->LI->LD
Esta propiedad bidireccional garantiza que nunca se pierdan enlaces en la navegación.

04 / 16 ALGORITMOS FUNDAMENTALES • PÁG. 81

Operación de Agregar: El Desafío de los 4 Punteros

La regla de oro para insertar un nuevo nodo N entre dos nodos existentes sin romper la cadena.

Lógica del Procedimiento de Inserción REGLA DE CONSERVACIÓN

A diferencia de una lista simple ligada (donde solo se modifican 2 punteros), en una lista doblemente ligada la inserción entre dos nodos existentes exige la reasignación estricta de 4 apuntadores.

¡Peligro Crítico de Memoria!

Si se modifica prematuramente A->LD = N antes de guardar o conectar con M, se pierde el acceso a toda la lista subsiguiente (Memory Leak e inconsistencia).

Regla de Oro: "Primero conecta los nuevos, luego rompe los viejos"

1. Conectar las ligas de N hacia los nodos existentes.
2. Redirigir las ligas de los nodos existentes hacia N.

Complejidad Computacional

Tiempo de ejecución: $O(1)$ (Tiempo constante, pues no requiere iterar si ya se tiene la referencia de inserción). Espacio: $O(1)$ adicional por nodo.

Pseudocódigo Formal y Asignaciones C / C++ EQUIVALENTE
// Inserción de un nuevo nodo N antes del nodo M
void insertarAntesDe(Nodo* M, TipoDato valor) {
  Nodo* N = new Nodo();
  N->INFO = valor;
  Nodo* A = M->LI; // Nodo predecesor existente

  // PASO 1: Liga derecha de N apunta a M
  N->LD = M;

  // PASO 2: Liga izquierda de N apunta a A
  N->LI = A;

  // PASO 3: Redirigir liga derecha del nodo A hacia N
  A->LD = N;

  // PASO 4: Redirigir liga izquierda del nodo M hacia N
  M->LI = N;
}

Mecánica del Algoritmo GESTIÓN DE EXCEPCIONES

El Puenteo de Punteros (2 Asignaciones)

1. El antecesor apunta al sucesor: B->LI->LD = B->LD;
2. El sucesor apunta al antecesor: B->LD->LI = B->LI;
3. Liberación de memoria física: delete B; o free(B);

Casos de Frontera Críticos

• Eliminar el Primer Nodo (B == I): Se debe actualizar el puntero externo de inicio: I = B->LD; I->LI = NULL;
• Eliminar el Último Nodo (B == D): Se actualiza el puntero de cola: D = B->LI; D->LD = NULL;
• Lista de 1 solo nodo: I = NULL; D = NULL;

Ventaja Suprema vs Lista Simple

En una lista simple, para eliminar el nodo B se debe forzosamente recorrer desde el inicio para ubicar al antecesor A ($O(n)$). En la doblemente ligada, como B ya conoce a su antecesor mediante B->LI, ¡el retiro es estrictamente $O(1)$!

El Nodo Cabeza Sombreado con Diagonales

En el dibujo de la pág. 82, destaca porque su área de datos está achurada. No almacena información de usuario; actúa como punto de referencia permanente o ancla señalado por el puntero p.

Eliminación Total de Casos Especiales

Al no existir punteros apuntando a NULL (tierra), las funciones de inserción y borrado jamás tienen que verificar if (p == NULL) para los extremos. Todo nodo tiene garantizado un antecesor y un sucesor válidos.

Comportamiento en Lista Vacía

Cuando la lista no contiene elementos de usuario, el nodo cabeza se apunta a sí mismo en ambas direcciones:
cabeza->LD = cabeza; y cabeza->LI = cabeza;

Aplicaciones en Sistemas Operativos

Planificadores de procesos (Round-Robin Scheduling), buffers circulares de audio/video y reproductores multimedia en bucle infinito.

08 / 16 COMPARATIVA ARQUITECTÓNICA • PÁGS. 82-83

Memoria Contigua (Arreglos) vs Ligada (Listas)

La pausa teórica del libro: por qué las listas transforman la gestión de grandes volúmenes de datos dinámicos.

Almacenamiento Contiguo (Arreglos / Arrays) BLOQUES PLANOS
[0]: A
[1]: B
[2]: C
[3]: D

Inserción y Retiro Costosos: $O(n)$

Para insertar un elemento en medio, es obligatorio desplazar físicamente en memoria todos los elementos posteriores una posición a la derecha. Si hay un millón de registros, se deben mover un millón de celdas.

Tamaño Fijo / Reubicación Masiva

Requiere declarar un tamaño estático inicial o realizar realocaciones de bloques completos cuando se agota el espacio (realloc).

Ventaja: Acceso Indexado Inmediato $O(1)$

Cálculo de dirección instantáneo mediante aritmética de punteros: dir = base + (i * tamaño).

Almacenamiento Ligado (Listas & Punteros) DINAMISMO PURO
Nodo A
⇄
Nodo B
⇄
Nodo C

Inserción y Retiro Eficientes: $O(1)$

No se mueve ningún elemento en memoria. Solo se cambian 4 punteros. No importa si la lista tiene diez o diez millones de nodos, la operación toma exactamente los mismos nanosegundos.

Flexibilidad Total en Tiempo de Ejecución

La estructura crece y decrece de nodo en nodo bajo demanda estricta; no requiere reservar bloques gigantes continuos de memoria.

Desventaja: Sobrecarga de Espacio & Acceso Secuencial

Cada nodo almacena 2 punteros adicionales. No permite indexación directa aleatoria (se debe avanzar con p = p->LD).

09 / 16 TEORÍA DE LÍNEAS DE ESPERA • PÁGS. 82-83

Colas (Queues): Disciplina PEPS / FIFO

El principio rector de las líneas de espera: Primeras Entradas, Primeras Salidas (First In, First Out).

Mecánica de la Cola PEPS / FIFO

Una cola simula de manera exacta una fila física de personas esperando atención para un servicio. La disciplina es estricta: el primer elemento en formarse es el primero en ser despachado.

Extremo Frente (Inicio / I / Front)

Por este extremo se realiza la operación Desencolar (Dequeue / Retiro). El elemento que llegó primero es atendido y abandona la cola.

Extremo Final (Derecho / D / Rear)

Por este extremo se realiza la operación Encolar (Enqueue / Inserción). Todo nuevo elemento entrante se coloca estrictamente al final.

¿Por qué usar Listas Dobles para Colas?

Permite mantener punteros tanto al Frente como al Final, garantizando que tanto la inserción como la extracción se realicen en $O(1)$ sin necesidad de recorrer la cola.

El balanceo de carga y los cuellos de botella (bottlenecks) dependen de la tasa de servicio $(\mu)$ y la tasa de llegada $(\lambda)$ según la fórmula de Little: $L = \lambda W$.

Detalles Gráficos de la Pág. 86 DESGLOSE TÉCNICO

El Principio UEPS (LIFO)

Últimas Entradas, Primeras Salidas (Last In, First Out). El elemento más reciente introducido en la pila es el primero absoluto en ser desalojado.

El Apuntador Externo TOPE (Top)

Señala invariablemente al nodo ubicado en la cúspide de la pila. Al hacer PUSH, el puntero sube; al hacer POP, desciende al nodo predecesor.

Fondo con Símbolo de Tierra (NULL)

El nodo inferior almacena un puntero nulo o tierra en su base, impidiendo desbordamientos negativos (Stack Underflow) cuando la pila se vacía completamente.
